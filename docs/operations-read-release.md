# 운영 읽기 화면 반영 준비

상태: 로컬 검증본. 원격 push, Pages, Edge Function 배포를 실행하지 않았다.

기존 공개 책방 회귀 주의: tests/visual/bookshop.spec.mjs는 a0cc248에서 제거된 #bookshop 화면을 요구한다. 전체 실행 시 이 항목들은 현재 운영 기준과 맞지 않아 실패한다. 이를 해결하려고 공개 화면을 복원하거나 테스트를 무조건 통과시키지 않는다. 관리자·서류·현재 홈페이지 회귀와 구분해 보고하고, 테스트 유지/폐기 범위는 별도로 정리한다.

## 사용

기존 관리자 로그인 후 ‘운영 읽기’ 메뉴(`#read`)에서 읽기를 실행한다. 재고 검색은 제목·ISBN·SKU를 찾는 용도이며 상품을 새로 연결하지 않는다. 품절·구매후보·판매가능 확인필요 필터를 제공한다. 장부·채널 기록·실물·예약·입고예정은 별도 값이다. 구매 후보는 주문 완료나 재주문 권고가 아니다.

API 조회시각과 원천 수집시각을 구분한다. 원천 전체수집 시각을 개별 SKU 재조회 시각으로 대체하지 않는다. 실패·미확인·미연결은 0으로 표시하지 않는다. 채널 판본 연결의 검증 정보가 없으면 채널 수량을 보류한다. 관리판 메모는 연결 검증을 대신하지 않는다.

프로그램은 기수 ID로 연결하며 이름으로 보정하지 않는다. 테스트 표시 신청, 미연결 신청, 기타 상태를 따로 드러낸다. 이름·연락처·이메일은 조회하지 않는다. 잔여석 원천값을 신청 건수로 다시 계산하지 않는다.

## 반영 범위

1. 정적 관리자 파일: admin/index.html 및 operations-read.js, operations-read-model.js, operations-read.css.
2. SCM Edge Function의 bookshop-model.mjs: 관리판 수집시각 전달 및 정확하지 않은 최소 수량을 미확인으로 보존.

DB 마이그레이션, RLS 변경, 계정·키 생성은 필요하지 않다. 메인 홈페이지·문고리·판매채널 재고·주문·결제·정산 파일은 변경 범위에 없다. 실제 원천 자료를 저장소에 포함하지 않는다.

## 운영 반영 전 조건

- 승인 후 최신 운영 브랜치와 비교하고, 현재 운영 Edge Function 원본을 비공개 로컬 백업으로 확보한다. 다른 작업을 덮어쓰지 않는다.
- 승인된 기존 프로젝트의 SCM 매퍼를 먼저 반영·검증한 뒤 정적 관리자 파일을 반영한다. 배포 도구의 기존 설정과 접근 권한을 유지한다.
- 기존 관리자 세션으로 새 #read 화면의 실제 검색·품절·구매 후보·프로그램·원천 상태를 확인한다. 로그인 확인이나 기존 화면 조회 성공은 새 화면 검증을 대신하지 않는다.
- 비인증 SCM 거부와 신청 행 비노출, 로그인 해제/권한 박탈 시 값 제거를 확인한다. 기존 공개 프로그램 목록 정책은 유지한다.
- 원천 갱신시각과 API 조회시각, 오래됨·실패를 구분하고 미확인 수량의 0 대체가 없는지 확인한다. 실제 원천 오류를 만들기 위해 운영 서비스를 중단하거나 권한을 변경하지 않는다. 오류 표시는 가상 응답으로 검증한다.

## 복구

정적 관리자 변경을 해당 기능 커밋 단위로 되돌리고 기존 Pages 경로로 반영한다. 전체 브랜치를 과거 시점으로 reset하지 않는다. Edge Function은 확보한 직전 원본으로 복원한다. 이 기능은 원본 데이터 쓰기를 수행하지 않아 데이터 롤백은 없다. 복구 실행에도 운영 반영 승인이 필요하다.
